# Contributing

## Engineering workflow

Changes should follow:

1. Inspect the repository and understand the affected subsystem.
2. Define a small, testable change.
3. Implement one responsibility at a time.
4. Run verification appropriate to the change.
5. Document architectural decisions where necessary.
6. Commit only verified work.

## Repository safety

Do not commit secrets, credentials, private keys, production data, or generated environment files.

High-risk operational changes require explicit human approval.
